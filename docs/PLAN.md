# 提示词优化工具：方案与资料

> 这是「言之」最初的项目方案，整理于 2026-10-22。V1 已按此方案实现，当前功能与用法以 [README](../README.md) 为准。

## 核心思路

AI 理解不了你，多半不是措辞问题，而是关键信息只在你脑子里、没写出来。所以好的优化工具，核心是帮用户把没说出口的信息挖出来，而不是把句子改漂亮。

一个好提示词通常补齐这五样：

| 要素 | 要回答的问题 | 例子 |
| --- | --- | --- |
| 背景 | 这是什么情况，为什么要做 | “我是刚入职的运营，要向领导汇报上周活动” |
| 任务 | 具体要 AI 做什么 | “写一份活动复盘” |
| 对象 | 结果给谁看 | “给不懂技术的部门负责人” |
| 要求 | 长度、语气、格式、不要什么 | “500 字以内，分三点，不要套话” |
| 例子 | 你满意的样子 | 贴一篇以前写得好的复盘 |

其中“例子”往往最管用，给一个样例比描述十句都有效。

## 工具的系统提示词

这是工具“大脑”用的提示词：工具每次调用 AI 时，把它作为系统提示词发过去。也可以先不做工具，直接把它粘贴到任意 AI 对话的开头来用。

```text
你是一个提示词优化助手。用户会给你一段写得比较粗糙的提示词，你的任务是帮他改成 AI 更容易理解、效果更好的版本。

用户通常不是专业人士，他们的问题往往不是措辞不好，而是缺少关键信息。所以请按以下步骤工作：

1. 先判断原提示词缺少什么。重点检查：背景、具体任务、目标读者、输出格式和长度、语气风格、限制条件、示例。
2. 如果缺少的信息会明显影响结果，先向用户提出最多 3 个问题，每个问题附上 2–3 个可选答案，方便用户直接选。不要问无关紧要的问题。
3. 用户回答后（或信息已经足够时），输出优化后的提示词。
4. 在优化结果下面，用 2–4 条简短说明解释你改了什么、为什么这样改，帮助用户以后自己也能写好。

要求：
- 保留用户的原意，不要擅自添加用户没有提到的目标。
- 优化后的提示词用自然、清楚的语言写，不要堆砌术语或夸张的角色设定（比如“你是世界顶级专家”）。
- 如果原提示词已经很好，直接告诉用户，只做小调整。
- 用用户使用的语言回复。
```

这段提示词本身就是按五要素写的：说清了背景（用户不专业）、任务、步骤、输出格式和限制，可以对照着学。

## 一键生成工具的构建提示词

把下面整段贴给 Claude（网页版或 Claude Code），它会生成一个单文件网页版的提示词优化工具。贴之前，把【系统提示词】那一行替换成上一节的完整内容。

```text
请帮我做一个「提示词优化工具」网页，交付一个可以直接在浏览器打开的单个 HTML 文件。

【背景】
我是编程新手，想做一个帮普通人写好提示词的小工具。目标用户不懂提示词技巧，写出来的提示词常常缺背景、缺要求。工具的核心是「先追问、再优化、再解释」，让用户用几次就学会自己写。

【功能（第一版只做这些）】
1. 设置：用户填入 API 地址、API Key、模型名，兼容 OpenAI 格式的接口（这样 DeepSeek、通义、Kimi 等都能用）。保存在浏览器 localStorage，不上传到任何其他地方。
2. 优化流程：用户输入原始提示词 → AI 返回最多 3 个追问，每个带可点选的选项（也可以自己填）→ 用户回答后输出优化结果。信息足够时可跳过追问。
3. 结果页：左右对比原始版和优化版；下方显示「改了什么、为什么」；优化版有一键复制按钮。
4. 场景模板：顶部提供 6 个常用场景按钮（写邮件、总结文章、写代码、改简历、翻译、写文案），点击后在输入框填入一个带空位的模板。
5. 历史记录：最近 20 条优化记录存在 localStorage，可以点开查看、删除。

【调用 AI 的方式】
- 系统提示词使用下方【系统提示词】。
- 为了方便页面解析，在系统提示词末尾加一条要求：只返回 JSON。追问阶段格式为 {"type":"questions","questions":[{"q":"问题","options":["选项A","选项B"]}]}；优化阶段格式为 {"type":"result","prompt":"优化后的提示词","changes":["改动说明1","改动说明2"]}。
- 解析失败时不要白屏：直接显示 AI 的原始回复，并提示「格式异常，可重试」。
- 请求失败时（Key 错误、网络错误、跨域被拦截）用中文告诉用户原因和怎么解决。

【界面要求】
- 全中文界面，简洁干净，支持手机屏幕和深色模式。
- 等待 AI 时显示加载状态，按钮不可重复点击。
- 不要用需要构建的框架，纯 HTML + CSS + JavaScript，代码加中文注释，方便我学习和修改。

【完成后】
告诉我：怎么打开使用；代码分哪几块、各自负责什么；如果我想加功能应该改哪里。

【系统提示词】
（在这里粘贴上一节的系统提示词）
```

两个常见坑：

- **跨域（CORS）**：有些厂商的接口不允许浏览器直接调用，会报跨域错误。解决办法是加一个小的后端代理，或者换一个支持浏览器调用的服务。
- **Key 安全**：这个版本只适合自己用。如果要发布给别人用，绝不能把自己的 Key 写进前端代码，必须放到后端。

## 功能清单与版本规划

第一版只做前三项，跑通并自己用顺了再往后加。

| 功能 | 作用 | 版本 |
| --- | --- | --- |
| 追问模式 | 先问清缺的信息再改，和普通“润色工具”的最大区别 | V1 |
| 解释改动 | 告诉用户改了什么、为什么，用几次就学会自己写 | V1 |
| 场景模板 | 写邮件、总结、写代码等填空式模板，降低起步难度 | V1 |
| 诊断打分 | 不改写，只指出缺什么，让用户自己补，适合想学习的人 | V2 |
| A/B 对比 | 同一任务分别用原版和优化版跑一次，并排看结果差别 | V2 |
| 反向生成 | 贴一段满意的成品，反推出能得到它的提示词 | V2 |
| 提示词库 | 保存好用的提示词，支持 `{{变量}}` 替换，下次直接复用 | V3 |
| 多模型适配 | 针对不同模型或生图工具生成不同风格的版本 | V3 |

V2 里的 **A/B 对比**最值得优先做：只看提示词本身很难判断好坏，看到两个输出并排放着，效果一目了然。

## 市面上类似的项目

最值得研究的是 linshenkx/prompt-optimizer：中文社区最火的同类开源项目，约 3.9 万 star（2026-10 查阅）。它采用 AGPL-3.0 协议：自己用、公司内部用都行，一旦修改后做成网站给别人用，就必须公开你的源代码。

| 项目 | 是什么 | 协议 | 怎么借鉴 |
| --- | --- | --- | --- |
| [prompt-optimizer（linshenkx）](https://github.com/linshenkx/prompt-optimizer) | 功能最全的提示词优化工作台：多轮优化、系统/用户提示词双模式、对比评估、变量和多轮测试、文生图、收藏库、MCP。有网页版、桌面版、Chrome 插件、Docker | AGPL-3.0 | 先用[在线版](https://prompt.always200.com)体验；读它的优化提示词模板和产品设计；二开若要对外发布须开源 |
| [LangGPT](https://github.com/langgptai/LangGPT) | 结构化提示词方法论和中文社区，上面项目的灵感来源之一 | 见仓库 | 学“好提示词长什么样”，可用来写你的场景模板 |
| [Anthropic 提示词优化器](https://www.anthropic.com/news/prompt-improver) | Claude 开发者控制台里的官方功能：改写提示词、管理示例、根据反馈反复迭代 | 商业产品 | 参考“给反馈 → 再优化”的交互；官方测试中分类任务准确率提升 30% |
| [promptfoo](https://github.com/promptfoo/promptfoo) | 提示词测试与评估工具：用一批测试用例跑多个提示词、多个模型，矩阵式对比结果 | MIT | 做 V2 的 A/B 对比时参考它的思路；2026 年 3 月被 OpenAI 收购，开源版后续走向未定 |
| [Promptimizer](https://github.com/SvetimFM/Promptimizer) | 自动优化框架：生成变体 → 批评 → 纠错 → 挑选，循环迭代 | Apache 2.0 | 偏研究，了解“自动优化”的算法思路即可 |

**建议**：不要直接 fork prompt-optimizer 做二开。它是大型 TypeScript monorepo（近千次提交），新手很难改动，功能也覆盖得很全。更好的路径是：用它当参考，自己从单文件版做起，把差异放在“追问 + 教学解释”上——这正是它没有主打的方向。
