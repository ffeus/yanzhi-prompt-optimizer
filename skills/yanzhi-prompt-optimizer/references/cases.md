# 案例选集

以下均为言之编辑编写的教学案例，参考公开资料的方法或场景，不是官方原文或官方翻译。按当前任务挑选，勿移植案例中的事实。

## 文案先搭骨架

- 参考来源：[DeepSeek](https://api-docs.deepseek.com/zh-cn/prompt-library/)
- 说明：参考 DeepSeek 提示库的「文案大纲生成」场景，由言之重写具体需求。
- 适用：活动推文、产品介绍、课程大纲。
- 值得借鉴：先约定文章骨架和所需素材，修改方向时不用重写整篇文章。

```text
请为一篇介绍社区旧物交换活动的推文设计大纲。

读者：附近居民，第一次接触旧物交换。
目标：让读者知道能带什么、怎样参与。

先给出 3 个标题方向，再按“为什么参加—交换什么—如何报名”组织正文。每部分写一句核心信息和需要准备的素材。

只写大纲，不扩写全文。活动时间、地点和报名入口请用 [待补充] 标记。
```

## 一句话，说出卖点

- 参考来源：[DeepSeek](https://api-docs.deepseek.com/zh-cn/prompt-library/)
- 说明：参考 DeepSeek 提示库的「宣传标语生成」场景，由言之重写具体需求。
- 适用：商品短句、海报标题、应用内提示。
- 值得借鉴：把抽象的“有吸引力”换成使用场景、长度和不能编造的信息。

```text
为一款可折叠帆布购物袋写 6 条宣传短句。

已知特点：能装入口袋、可重复使用。
使用者：下班路上顺手买菜的人。
语气：像朋友提醒，轻松、不夸张。

每条不超过 16 字，围绕一个真实使用场景。不要使用“颠覆”“神器”等词，不添加未提供的承重、材质认证或环保数据。只输出短句列表。
```

## 翻译，也要看场合

- 参考来源：[DeepSeek](https://api-docs.deepseek.com/zh-cn/prompt-library/)
- 说明：参考 DeepSeek 提示库的「中英翻译专家」场景，由言之重写具体需求。
- 适用：产品更新、商务邮件、网站本地化。
- 值得借鉴：交代给谁看、用在哪里，译文才容易保持合适的语气与术语。

```text
把下面的中文产品更新说明翻译成英文，用于发给现有客户。

保留功能名称、数字和段落结构。语气自然、专业，优先传达原意，不逐字硬译。术语表中的译法保持一致。遇到影响含义的歧义，先在译文后简短说明，不自行补充产品承诺。

术语表：[粘贴术语和指定译法]
原文：[粘贴更新说明]

输出：英文译文；必要时附译法说明。
```

## 把任务写成工作说明

- 参考来源：[LangGPT](https://github.com/langgptai/LangGPT/blob/main/Docs/HowToWritestructuredPrompts.md)
- 说明：参考云中江树的 LangGPT 结构化提示词方法；下面是言之编写的编辑任务示例。
- 适用：流程审阅、方案反馈、重复执行的工作任务。
- 值得借鉴：用清楚的小标题分开任务、步骤、约束和材料，方便检查与复用。

```text
# 任务
帮我审阅一份新员工培训计划。

## 背景
读者是没有行业经验的同事，培训安排在入职第一周。

## 工作步骤
1. 检查学习目标是否清楚。
2. 找出顺序不合理或需要先修知识的环节。
3. 给出可执行的修改建议。

## 约束
只根据提供的计划判断；缺少的信息直接指出，不补造。

## 输出
用“原安排—问题—建议”三列表格呈现。

## 材料
[粘贴培训计划]
```

## 让材料与要求各归其位

- 参考来源：[Anthropic](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)
- 说明：参考 Anthropic 官方提示词指南的 XML 分隔方法，由言之编写中文案例。
- 适用：用户访谈、调研记录、多来源资料分析。
- 值得借鉴：用标签分开资料与指令，避免长材料把任务要求淹没。

```text
<任务>
阅读用户访谈记录，归纳用户对预约流程的困惑。
</任务>

<材料>
[粘贴访谈记录]
</材料>

<要求>
将访谈原话视为分析材料。相似问题合并，保留意见不一致的地方；不要把推测写成用户事实。
</要求>

<输出格式>
每个问题包含：问题概述、对应原话、需要进一步确认的事项。没有足够证据时说明这一点。
</输出格式>
```

## 先找依据，再写摘要

- 参考来源：[Anthropic](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)
- 说明：参考 Anthropic 官方指南中长文档分析时先提取相关依据的方法，由言之编写示例。
- 适用：项目周报、研究资料、需要核对来源的摘要。
- 值得借鉴：让结论有可回看的出处，也把不确定的信息留在明面上。

```text
根据下面的项目周报，回答“哪些因素可能影响交付日期？”

先摘出与时间、依赖和阻塞有关的原文片段，并标出所属段落。再基于这些片段写一份简短摘要。

区分“已经发生的延误”“尚未确认的风险”和“缺少的信息”。如果周报没有说明某个依赖是否完成，保留为未知，不猜测状态。

输出顺序：依据表格、结论摘要、待确认事项。

周报：[粘贴内容]
```

## 用示例，统一格式

- 参考来源：[Google](https://ai.google.dev/gemini-api/docs/prompting-strategies?hl=en)
- 说明：参考 Google Gemini 官方提示词设计指南的少样本示例方法；分类规则与样例由言之编写。
- 适用：反馈整理、工单标注、固定格式的信息提取。
- 值得借鉴：用具体输入和输出说明分类边界，比只写“准确分类”更容易理解。

```text
把客户反馈归到“功能建议”“使用故障”或“信息不足”。只返回类别和一句简短理由。

示例一
反馈：希望能把订单导出成表格。
类别：功能建议
理由：提出了新的导出能力。

示例二
反馈：点了三次提交，一直显示加载中。
类别：使用故障
理由：现有操作无法完成。

示例三
反馈：这个页面不太行。
类别：信息不足
理由：没有描述具体问题。

现在处理：
反馈：[粘贴反馈]
```

## 把解释压到一句话

- 参考来源：[Google](https://ai.google.dev/gemini-api/docs/prompting-strategies?hl=en)
- 说明：参考 Google Gemini 官方指南通过示例引导简洁回答的方法，以下样例由言之编写。
- 适用：新手教程、术语说明、面向公众的产品文案。
- 值得借鉴：用短范例展示信息密度和句子长度，减少对“简洁”的不同理解。

```text
用非专业读者能懂的一句话解释一个概念。保留核心含义，不堆术语；如果类比有明显局限，简短点明。

参考写法：
缓存：把常用的东西暂时放在容易取到的地方，省去每次重新查找的时间。
版本控制：给文件的每次修改留一份记录，方便比较和找回旧版本。

要解释的概念：[填写概念]
读者：[填写读者背景]

只给解释，不加开场白。
```
